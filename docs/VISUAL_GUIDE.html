Plugin Manager Sidebar

Every installed and built-in plugin in one sidebar: search, toggle, pin, group, update, rename, and remove. This dashboard explains the promise, the host bridges, and the rules that must survive future edits.

What it is for

The short version a new maintainer needs before touching code.

Manage in place

Enable, disable, pin, and open settings without leaving the sidebar or visiting two settings pages.

One honest inventory

Community and core plugins share one list built from Obsidian's own manifests, so there is no cached copy to drift.

Groups that are only a view

Grouping never moves or mutates plugins; it creates sections and bulk actions over the same list.

Updates where you look

The header badge, Updates filter, and section all read Obsidian's own update table and install through it.

Rename without breaking installs

Local plugins are edited on disk; official and core plugins get a reversible overlay in data.json.

Failures stay contained

Every action runs through a safe wrapper and a single-operation lock, so one bad host call cannot blank the list.

System map

The view delegates every mutation; only the plugin core touches Obsidian internals.

Feature contract

If a change breaks one of these, it is a regression, not a refactor.

Verified toggles

After enable/disable the state is re-read from the host; a mismatch throws and is reported.

Self-protection

The manager's own switch is locked and both uninstall and bulk actions refuse its id.

Group merge

Editing a group keeps ids for currently missing plugins instead of dropping them.

Update delegation

Discovery and install come from Obsidian's update table; no separate downloader exists.

Overlay reset

Official metadata overrides can be cleared back to the host's manifest at any time.

Serialized saves

Rapid clicks cannot persist an older settings snapshot after a newer one.

Two-row controls

Scope/view/group stay reachable even when every filter is on.

Ordered refresh

Views refresh in finally, after the mutation finished, with scroll restored.

Decisions worth knowing

Each one replaced a specific failure.

Chosen

Capability checks

Every private host API is optional and probed with typeof, with a fallback chain.

Chosen

Overlay for official plugins

Rewriting official manifests loses the edit on update and cannot work for core plugins.

Chosen

One mutation at a time

A busy guard prevents overlapping installs, group batches, and interleaved notices.

Chosen

Total sanitizer

Any stored blob becomes valid settings; prototype keys and bad enums never reach state.

Chosen

Best-effort badges

If the registry is unavailable, rows show no source badge rather than a wrong one.

Chosen

Host update bridge

Obsidian owns version resolution and installation; the sidebar only orchestrates.

Landmines

The failures that look like small cleanups until they break a user's setup.

Trap

Self-disable

Disabling this plugin unloads the code mid-action and leaves a dead view.

Trap

data.json v7

Unknown keys are dropped silently; read old keys before renaming anything.

Trap

Missing internals

app.plugins can be undefined on mobile or during startup.

Trap

Desktop-only require

window.require("electron") throws off desktop; always fall back.

Trap

Pinned duplication

Render pinned rows once, or counts double and two switches target one plugin.

Trap

Core plugin shape

Core objects expose setEnabled, or method pairs, or only a flag.

Trap

Invalid manifest JSON

Always fall back to the in-memory manifest when the file cannot be parsed.

Trap

runtime/ drift

The frozen bundle is the user's rollback. Never build into it.
